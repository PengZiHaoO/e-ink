# NFC 磁吸 · 无电池电子纸 —— 产品方案 V1

> **目标产品：** 85.6 × 54 mm 左右的 3.7" 黑白电子纸，MagSafe 磁吸，无电池，NFC 碰一碰更新。

---

## 0. 文档说明

| 项目 | 内容 |
| --- | --- |
| 版本 | V1（可开始原理图 / PCB 设计的收敛版） |
| 日期 | 2026-08-26 |
| 状态 | 方案冻结，进入工程验证阶段 |
| 核心原则 | **先验证能量预算，再画最终 PCB** |

### 本次修订修正的过度乐观假设

1. **3.7" + 800×480 + NFC 无电池供电是高风险组合** —— 第一版必须首先验证能量预算。
2. **NTAG I²C 不适合作为大型电子纸的供电源** —— 通信能力与供电能力必须分开设计、分开优化。
3. **超级电容不是"电池"**，它的定位是 *Refresh Energy Buffer*（单次刷新的能量缓冲），不是用来维持设备持续运行。
4. 不把 **$39 / 4mm / 3.7寸 / 800×480** 全部当作既定事实，由 Go / No-Go 实验先行裁决。

## 1. 产品定义

| 维度 | 规格 |
| --- | --- |
| 产品形态 | NFC 碰一碰更新的无电池电子纸 |
| 屏幕 | 3.7" 黑白电子纸 |
| 供电 | NFC 13.56 MHz 无线取能 + 超级电容缓冲 |
| 磁吸 | MagSafe 兼容 |
| 通信 | NFC（无 BLE、无电池、无 IMU） |

### 核心体验流程

```text
手机靠近/碰触
      ↓
NFC建立通信 + 取能
      ↓
储能电容充电
      ↓
MCU唤醒
      ↓
接收图片/Widget数据
      ↓
电子纸刷新
      ↓
系统重新进入超低功耗
```

> 平时电子纸**不需要供电也能保持画面**。

## 3. 屏幕：3.7" / 800×480

这是目前锁定的目标规格。

### 目标参数

| 项目 | V1 目标 |
| --- | ---: |
| 尺寸 | 3.7" |
| 分辨率 | 800 × 480 |
| DPI | ≈220 |
| 颜色 | 黑 / 白 |
| 接口 | SPI |
| 刷新 | 全刷优先 |
| FPC | 是 |
| 厚度 | 尽量 < 1 mm |

### ⚠️ 选型原则：不要现在锁死 Driver IC

> 先找 3.7" 800×480 低功耗电子纸 → 看厂家实际 Driver IC → 再适配 MCU。

该尺寸可能出现 **UC8176、SSD1677** 等驱动方案，以实际采购到的屏幕为准。

## 4. MCU

### 首选：STM32U031

- 超低功耗
- Cortex-M0+
- SPI
- RAM / Flash 比 L0 系列更适合图像缓存和协议处理
- 新一代低功耗平台
- 成本仍然较低

### 备选：STM32L011

- 若 V1 数据处理非常简单，完全够用
- 成本更低

### MCU 主要工作

```text
NFC数据
   ↓
协议解析
   ↓
图片解压
   ↓
Frame Buffer
   ↓
SPI
   ↓
E-Ink
```

同时负责：

- 电压检测
- 电容电量检测
- 屏幕状态控制
- NFC 事件唤醒
- 异常复位

---

## 5. NFC 与能量获取（重点重设计）

这是整个项目**最大的技术风险**。

### 原思路的问题

不建议简单地：

> NT3H2111 → 直接给 3.7" 屏供电

NTAG I²C 这类芯片首先是 **NFC 通信 / Tag 产品**，并非为给大型电子纸刷新提供大量能量而设计。

### 正确架构

```text
                  NFC Coil
                     │
              13.56 MHz RF
                     │
          ┌──────────▼──────────┐
          │ NFC Front End       │
          │ + Energy Harvest    │
          └──────────┬──────────┘
                     │
             ┌───────▼───────┐
             │ Energy Storage │
             │ 10~100mF      │
             └───────┬───────┘
                     │
                  3.3V Rail
                     │
          ┌──────────┴─────────┐
          │                    │
         MCU                 E-Ink
```

### 分阶段策略

| 阶段 | 方案 | 目的 |
| --- | --- | --- |
| 第一阶段 | NXP NT3H 系列开发方案 | 快速验证通信 + 取能 |
| 第二阶段 | 专用 NFC Energy Harvesting 方案 | 提高实际可用功率 |

> **通信能力和供电能力分开优化。**

## 6. 储能电容（超级电容）

### 定位：Refresh Energy Buffer，不是电池

```text
手机NFC靠近
       ↓
持续收能
       ↓
超级电容电压上升
       ↓
达到启动阈值
       ↓
MCU启动
       ↓
刷新电子纸
       ↓
电容放电
       ↓
完成
```

### 容量选择：逐级实测

V1 建议测试：**10mF / 22mF / 47mF / 100mF**

> 不要一开始就决定 100mF。实际需要多少，要通过示波器实测后反推：
>
> - NFC 输入功率
> - 电容充电时间
> - E-Ink 峰值电流
> - MCU 峰值电流
> - 一次完整刷新消耗的能量

## 7. 供电架构

```text
NFC
 │
 ▼
RF Rectifier / Harvest
 │
 ▼
储能电容
 │
 ▼
Power Path
 │
 ├──── MCU 3.0/3.3V
 │
 └──── E-Ink电源
```

### ⚠️ 注意

**不要简单使用一个普通 LDO 把所有东西串起来** —— 电子纸刷新有瞬时电流。

需要做：

- 欠压检测
- Power Good
- 电容电压检测
- MCU brown-out
- E-Ink 独立供电控制

## 8. NFC 天线

第二大技术风险。

### 优势

产品尺寸 **85.6 × 54 mm** 给 NFC 线圈提供了非常好的面积。

### 建议方案：FPC NFC Coil

不要一开始就用 PCB 小线圈。

```text
┌────────────────────────┐
│  ╔══════════════════╗  │
│  ║                  ║  │
│  ║    E-INK区域     ║  │
│  ║                  ║  │
│  ╚══════════════════╝  │
└────────────────────────┘
```

### 目标与测试

**13.56 MHz 精确调谐。** 需要实际做：

- VNA 测试
- 手机实测
- 不同 MagSafe 手机实测
- 不同磁吸位置实测

---

## 9. MagSafe 与 NFC 的堆叠

结构设计中**最容易踩坑**的地方。

### 建议堆叠（自上而下）

```text
正面
│
├─ 保护层
├─ E-Ink
├─ FPC
├─ 主PCB
├─ NFC线圈
├─ 铁氧体隔磁
├─ MagSafe磁铁
├─ 后盖
│
手机
```

### ⚠️ 不要凭经验定线圈与磁环的位置

需要做 **2～3 种结构样**，然后直接测手机实际取电功率：

| 方案 | 说明 |
| --- | --- |
| A | NFC 线圈在磁环内 |
| B | NFC 线圈包围磁环 |
| C | NFC 线圈与 MagSafe 区域部分错位 |

## 10. PCB

### V1 建议：4 层板

原因：

- 电源完整性
- NFC 区域布局
- MCU 与 E-Ink 高速信号
- EMI 控制
- 后续调试空间

### 布局：主板不需要铺满整个银行卡面积

建议 **30 × 40 mm 左右主板**，剩余区域留给：

- NFC 天线
- 屏幕 FPC
- 结构件

## 11. 功能取舍（V1 明确砍掉）

| 项目 | 状态 |
| --- | --- |
| IMU | 砍掉 |
| BLE | 砍掉 |
| RTC | 砍掉 |
| 电池 | 砍掉 |

> **原因**：无源产品不应该一直运行。超级电容的用途是完成一次刷新，而不是维持设备运行。

V1 的软件流程非常干净：

```text
NFC触发
 ↓
刷新
 ↓
断电
```

## 12. 手机端通信协议

硬件侧不需要 BLE，采用 **NFC** 承载数据。

### 数据帧格式

```text
Header
Version
Device ID
Image Size
Compression Type
Image Data
CRC
```

### 图片数据量控制

800×480 黑白原始数据：

**48 KB 原始数据** —— 不建议直接传输。

建议压缩方案：

- RLE
- Tile compression
- 差分更新

> 目标：把典型 Widget 压缩到 **几 KB ~ 十几 KB**，明显缩短 NFC 传输时间。

## 15. 工程验证顺序

> **不要直接开始画最终 PCB**，先完成四个实验。

### EVT-0：能量实验

```text
手机NFC
 ↓
线圈
 ↓
Harvest
 ↓
电容
```

测：**手机贴上后到底能获得多少 mW。**

### EVT-1：电子纸实验

```text
电容
 ↓
3.3V
 ↓
MCU
 ↓
3.7" E-Ink
```

测：**一次完整刷新需要多少 mJ。**

### EVT-2：合体实验（最关键）

```text
手机
 ↓
NFC
 ↓
磁环
 ↓
铁氧体
 ↓
线圈
 ↓
电容
 ↓
E-Ink
```

**通过标准：**

> 手机贴上 3~5 秒，可以稳定完成一次刷新 —— 产品基本成立。

### EVT-3：极限测试

测试覆盖：

- iPhone 不同型号
- Android 不同厂商
- 手机壳
- MagSafe 位置偏移
- NFC 线圈偏移
- 温度
- 电容初始电压

## 17. Go / No-Go 指标

### 第一阶段只回答一个问题

> **手机 NFC 在 MagSafe 完整结构存在的情况下，能不能在合理时间内提供足够能量，让 3.7" 800×480 电子纸完成一次可靠刷新？**

| 结果 | 动作 |
| --- | --- |
| **Yes** | 继续做 |
| **No** | 不要先换 MCU，按以下优先级依次调整 |

**调整优先级：**

```text
屏幕分辨率 → 屏幕尺寸 → NFC线圈 → 磁环结构 → 刷新策略
```

> 这比直接进入最终 PCB 设计靠谱得多。

---

## 附录：关键设计原则速记

1. **能量预算优先** —— 所有规格以 EVT-0 / EVT-2 实测数据为准。
2. **通信与供电分开优化** —— NFC 通信芯片 ≠ 能量取用芯片。
3. **电容 = 刷新缓冲，不是电池** —— 用完即断电。
4. **屏幕驱动 IC 以实际采购为准** —— 不预先锁定型号。
5. **结构与 RF 协同验证** —— 线圈 / 磁环位置用结构样实测，不凭经验。
