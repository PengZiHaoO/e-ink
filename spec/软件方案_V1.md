# NFC 磁吸 · 无电池电子纸 —— 软件方案 V1

> **定位：** 硬件负责把这个东西变成现实，**App 负责让这张卡"有生命"**。
> 软件不是"电子纸图片传输工具"，而是 —— **「手机背面的第二个信息层」**。

### 核心论点

软件不应该做成"电子纸图片传输工具"，否则会很快退化成：

> 选图片 → 黑白化 → NFC 发送

**这没有壁垒。**

真正要定义的软件命题是：

> **什么信息值得离开手机屏幕，变成一个永远存在的实体状态。**

---

## 1. 软件定位：「手机背面的第二个信息层」

核心不是"显示什么"，而是信息的**实体化**：

- 手机通知 → 看完就消失（易失信息）
- 手机背面电子纸 → 永远存在的实体状态（持久信息）

这是一块放在手机背面的、**随语境变化的数字身份卡**。

---

## 2. 核心差异：Dynamic Card，而不是图片

用户不是上传一张图片，而是创建一张 **Card**：

```text
┌──────────────────┐
│                  │
│   ALEX CHEN      │
│                  │
│   PRODUCT DESIGN │
│                  │
│   ● AVAILABLE    │
│                  │
│      QR CODE     │
└──────────────────┘
```

Card 背后有**数据**，例如：

- 当前时间
- 日程
- 音乐
- 状态
- 二维码
- 天气
- 倒计时

App 自动把数据渲染成电子纸画面。

> 用户感觉不是"我在给屏幕传图片"，而是：
> **"我有一张会自动更新的实体卡片。"**

## 4. 最有价值的功能：一张卡，多种状态

用户的电子纸随语境切换：

```text
平时：   Personal
办公室： Work
开会：   Meeting
下班：   Personal
```

电子纸不需要一直在线。App 只需要：

> **在下一次 NFC 交互时，把最新状态写进去。**

这非常契合无源硬件的特性。

---

## 5. "Smart Refresh"：核心软件技术

**不要每次都全量刷新。**

```text
旧画面
+
新状态
        ↓
Diff Engine
        ↓
只更新变化区域
```

示例：

```text
10:30 Meeting   →   11:00 Meeting
```

只变化数字区域。

### 收益

- 减少 NFC 数据量
- 减少屏幕刷新
- 减少取能时间
- 提升体验

> 这会**直接反过来帮助硬件**（见硬件方案的 EVT-2 能量预算）。

## 7. AI：一个很好的差异点

**但不要做"AI 聊天机器人"，那没有意义。**

AI 的职责是**自动设计你的背屏**。

### 场景示例

> "今天我要去见客户，帮我设计一个低调一点的商务状态。"

AI 生成：

```text
ALEX CHEN

CLIENT MEETING

14:00

Available after 15:30
```

并自动完成：

- 排版
- 黑白化
- 选择字体
- 生成二维码
- 控制信息密度

### 更进一步

> "帮我做一个像 90 年代掌机一样的黑白主题。"

直接生成电子纸 UI。

## 8. "Physical Notification"：有意思的方向

手机通知通常看完就消失。电子纸可以把重要信息变成**物理存在的提醒**：

```text
┌────────────────┐
│                │
│  PICK UP        │
│                │
│  PACKAGE        │
│                │
│  16:30          │
│                │
└────────────────┘
```

### ⚠️ 注意

如果没有后台权限，App 不能保证实时更新。

- 第一代**不要宣传"实时通知"**
- 可以承诺：**下一次碰触时自动同步最新状态**

---

## 9. "One Tap / One Touch"：交互语言

整个产品尽量只有一个动作。

### 设计

```text
App 里：
Save
  ↓
手机靠近：
Tap
  ↓
完成。
```

### 不要

> 打开App → 连接设备 → 配对 → 选择设备 → 上传 → 等待……

**因为产品最大的优势就是：没有电池、没有配对、没有充电。**

软件也应该保持这种极简。

---

## 10. App 首页：不要做"设备管理"

传统 IoT App：

```text
My Devices
    ↓
Device 01
    ↓
Settings
    ↓
Firmware
```

这非常像小米 / 智能家居。

我们应该做：

```text
             CURRENT CARD

          ┌──────────────┐
          │              │
          │  ALEX CHEN   │
          │              │
          │   AVAILABLE  │
          │              │
          └──────────────┘

      [ Work ] [ Personal ]

             TAP TO UPDATE
```

> 用户打开 App 第一眼就看到："现在我的手机背面是什么？"

不要让用户觉得自己买的是一个"电子纸屏幕"。

应该让他觉得自己买的是：

> **一张长在手机背后的、可以随时改变的数字身份卡。**

硬件：把这张卡变成现实（见《产品方案_V1.md》）
